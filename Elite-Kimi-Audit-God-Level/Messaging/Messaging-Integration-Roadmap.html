Messaging Integration — the road to Luke

N-Program · ratified 2026-07-25 · plan: Messaging-Integration-Plan.md · sealed capability: @novakai/messaging (253/253, scorecard 97.0)
The promise: the app's messaging becomes the sealed capability — pushed, durable, policy-true — then the door opens to external terminals, then Slack, then one shared cross-company channel with Luke's team. The core never changes; everything attaches through seams or speaks the published protocol.

The four phases

PHASE 1

Rock solid inside the app

Replace the old messaging surface slice by slice. Each slice: build → audit → dispose → commit. Old path deleted, never dual-run.
N1
Foundation — package embedded in the backend; adapters wired to the app's agent/team/mission truth. Exit: boots in-app, all gates green. SEALED 2026-07-25 — audit moderate, findings disposed (Messaging-N1-Review.md); PR #63 open.
N2
Agent direct lane — 1-1 messages through the capability; PTY delivery via the terminal submit lane. Exit: two live agents converse; old router path gone.
N3
Rooms — #team and rooms become room Threads with frozen member snapshots. Exit: room send reaches exactly the members; blocked never receives.
N4
Frontend — Messages tab + Mission Control run on pushed events. The big one. Exit: inbox updates with zero polling.
N5
Kill the pollers — watchdog, transcript scanner, mailbox-scan habits all die. Exit: no interval touches the journal; failures push.
PHASE 2

Open the door

External terminals become first-class — tokens, TLS, a connect-your-agent flow. The protocol is already proven (P2/P3); this makes it operable.
N6
External access Exit: an agent on a foreign machine connects and messages — no manual step.
PHASE 3

Slack bridge

A small daemon that is a client of Messaging — Slack channel ↔ app room, both directions, echo-safe, real identities.
N7
Slack bridge (our workspace) Exit: message from Slack shows in the app; agent reply shows in Slack.
PHASE 4★

The Luke moment

Same bridge pointed at a Slack Connect channel between the two companies. Cross-company room, explicit allowlist, deny-by-default guarding everything.
N8
Cross-company channel Exit: a Novakai agent posts → Luke's team sees it in their Slack → their reply lands in the app with real delivery truth.
  • The one thing code can't control: Luke must accept the Slack Connect invite. Start that conversation during Phase 1.

Risks being watched

  • N4 is the beast — 6,300 LOC of old frontend retires; split internally if the diff gets un-auditable.
  • Echo loops — the bridge drops its own posts; loop-hunt tested before N7/N8 seal.
  • Spoofing — identity comes from authenticated Slack user IDs, never message text.
  • Slack edits/deletes — immutable history wins; edits appear as follow-up notes.
  • Governance — bridged content leaves our infrastructure; deny-by-default contact policy stays the gate.
